# 执行、验收及固定流程迁移

## 当前执行职责

Codex 主分析上下文核验来源、安排三个独立分析上下文、审查和合并；每路 Codex 负责全部推理及 JSON 内容。CLI 是数据/校验工具，不调用模型。Python 的序列化、文件复制和校验可以使用，但不能用程序模板批量冒充分析结论。

每路接收共同快照 ID/哈希、自己的 branch、合同版本、分析时间口径、输出目录及本 Skill 必读资料。不给旧报告结论、兄弟结论或主上下文预先指定的业务答案。查询可逐步进行，不是整包一次生成。某路失败可以保留其他已完成结果，但不得标记整份报告完成。

## 工序输入输出

以下是迁移设计合同；当前 CLI 只实现 prepare/query/validate，不声称已有自动状态机、锁、定时器或发布器。

| 工序 | 输入 | 输出与通过条件 | 失败处理 |
| --- | --- | --- | --- |
| scope | 用户环境/时间/范围 | 明确口径的 run manifest | 不明确则等待信息，可继续只读环境检查 |
| source_preflight | 已有连接及目标 | 真实主机/镜像/路径/CLI 记录 | 不匹配则 blocked，不回退 |
| freeze | 已核验目标与范围 | snapshot.json、manifest、哈希、闭包完整 | drift 可有限重试；缺源/未完成/不支持需查明原因 |
| branch_prepare | 冻结快照、三类范围 | 各路 Event/Signal/Evidence 清单和计数 | 跨范围混合 Signal 阻断对应路，不静默剔除 |
| analyze × 3 | 本路原始数据与方法 | 本路 report、audit、review | Codex 修正本路，不送入其他路结论 |
| branch_review | 本路产物和范围清单 | 覆盖与语义审查记录 | 把具体缺陷交回本路 |
| combine | 三路已审查产物 | 完整 report.json；只组合不重推理 | 身份/引用冲突定位归属，不统一业务方向 |
| validate | 报告、原快照、合同 | 结构来源校验 + Codex 语义覆盖审查均通过 | 按具体缺陷修正，重新生成受影响凭据 |
| finalize | 有效报告及凭据 | completed、最终哈希、交付路径与限制 | 有未解决错误不完成 |

建议运行状态：prepared、analyzing、reviewing、validated、completed、blocked、failed。由未来确定性流程控制；每次状态记录原因、输入哈希、方法/合同/代码版本、产物哈希。不能把模型自己声称“通过”当校验结果。

## 可恢复性与副作用边界

一次运行对应一个冻结数据版本；另一次重新取数使用新 run，不能覆盖旧快照。来源读取超时可以重试并重新验证完整快照，不拼接有漂移的页；业务语义失败不能靠无上限重复生成掩盖。保存完成工序及失败原因。

同一输入哈希、工序、方法和合同版本的完成产物可在明确恢复时复用，校验哈希后继续；方法/范围/输入变化则重新推理受影响工序。默认新报告请求不是复用旧结论。建议未来幂等身份由目标环境、时间口径、snapshot hash、方法/合同版本组成，实际重跑 attempt 单独编号。

未来不要在长时间 Codex 推理期间持有全局排他锁；只在创建运行身份、提交状态或发布等短副作用处做原子互斥。并行独立工序由流程控制，不让模型管理锁、数据库事务或补偿。

HTML、Data Service 发布、定时调度都是后续独立工序：HTML 从已验收 JSON 渲染；发布前单独验证服务兼容性和授权，保存 receipt，不重新推理；调度只能调用已验收流程。当前 v6-draft 未获服务发布验收，不可自动发布。

## 必须完成的审阅

1. 数据覆盖：每路输入 Event/Signal ID 集合与 audit 一一对应，分页无遗漏；每条记录有采用/限定/排除理由和结果位置。不能以只展示部分来源代替全量分析。
2. 来源闭包：每个信号的 Event、Evidence、变量、自身实体均真实且在范围内；不能偷引其他工序信号或把历史报告作为证据。
3. 变量综合：可比口径不重复分组；每信号在互斥证据类中恰好一次；冲突不是投票，错挂不被当作业务变化。
4. 传导：每个推理有根事实、机制、敞口、条件和时滞；没有自身信号的锚点不被标 direct；结构边不被当作事实因果。
5. 节点与链：真实成员/边、图与判断一致、无暂无评估占位、无空链、无跨公司错配。公司因素和上层因素有使用或未使用的解释。
6. 产品语义：标题是正式名称；类型独立；结论无状态前缀；方向中文；总结/详情对象、结论、影响度及证据一致；保留必要的不确定性。
7. 独立性：三路上下文不互读；不同范围同实体结论可以不同；合并不把本路结论强加给另一路。
8. 结构验收：执行 CLI validate，并单独记录语义/覆盖审查。CLI 不能证明全文已分析、推理正确或 Data Service 已支持。

## 行为验收场景

使用原始数据构造或选择这些情况检验 Skill，而非仅检查文档关键字：

- 地缘 Event 的 Signal 挂在宏观/公司：仍须读取；该锚点的其他非地缘 Event 不得自动引入。
- 一条 Signal 跨地缘和宏观来源：两路不得裁剪来源后继续；产业若全部来源在范围内可以分析，但不能掩盖前两路未完成。
- 无 Signal 的 Event：仍审阅，不能自动排除；不凭事件存在强造产业链。
- 同向多证据、反向事实、不同产品或同比环比：分别得到合并、冲突解释或明确范围拆分。
- 公司错配、有效期已过、政策愿望与正式决定不同：有明确判断和限定，不改原始信号。
- 节点无可信路径：图和详情不出现；有效上下游可评估时不得只留一个示例节点。
- UAT 不通、本地可通：必须阻断；按入库时间取数时未来生效计划仍须纳入；CLI 缺少所需时间选项时阻断，不能宣称全量已覆盖。
- 文案编辑后：JSON/HTML/校验 hash 同步，旧审计不能被当作新版本通过凭据。

完整 UAT 运行是最终行为验收；文档格式及引用检查通过只能证明 Skill 可读取。
