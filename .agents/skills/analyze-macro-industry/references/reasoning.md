# 宏观经济与产业链基本面推理

每路独立读取 data-contract.md、variables-and-transmission.md、report-contract.md 和自己的原始输入。输出本路产品部分及 audit/review；不要读取其他工序结果或历史报告结论。

## 宏观经济

1. 从本路 Event 定位真实 MacroEconomic；区分政策目标、正式决定、实施动作、实际流量以及经济结果。政府降息诉求不是利率决定，逆回购公告不是降准或净投放，计划支持不是实际资本开支。
2. 以范围内信号和 Event 综合相关变量，核对存量/增量、总量/结构、名义/实际、同比/环比、季节性、基期、修正值、实际/预期。没有可比数据时不能把单点值写成变化趋势。
3. 判断增长/需求、通胀/投入成本、利率/融资、信用/流动性、汇率/贸易等与当前故事线相关的渠道；不要求每次都覆盖所有宏观维度，不擅自补市场数据。
4. 将宏观渠道落到行业业务机制：终端需求如何影响订单，融资条件如何影响资本开支，成本能否传价，哪些区域/产品实际暴露。政策宽松不自动使全部产业升温，通胀上升不自动等于所有企业利润下降。
5. 选真实 IndustryChain，继续定位节点；结合需求、供给、成本、传价、库存和时滞形成链与节点结论。总结只列受影响产业链，详情字段与产业工序一致。
6. 明确反向事实及政策传导阻力，把子行业受益与宏观总量结论分开。宏观工序不引用地缘工序结论；需要的地缘背景只有已在本路 Event 中的部分可作为来源事实。

## 产业链推理及公司数据的使用

1. 独立阅读四类全部 Event/Signal；先处理各实体变量，建立本工序的地缘、宏观、公司和产业原始判断，不读取 Research 报告或宏观兄弟报告。
2. 从真实链/节点/公司关系定位暴露。链按功能、产出及节点归属识别；“输入性能源价格压力”是宏观故事线，不是临时创造的产业链。公司同名错配时不能借用其他公司的订单和产能。
3. 对节点分析需求/订单/交付、供给/产能/利用率、库存、成本/价格/价差、技术替代、资质准入、资本开支、利润和现金流，限于输入可支持的维度。区分需求改善与供给扩张；供给增长既可能增加销量，也可能压价。
4. 自上而下在本工序重建地缘/宏观→链→节点的影响；自下而上审查公司业务→节点→链。单家公司变化不能自动推广到全行业，需代表性、规模、份额或真实业务敞口依据；不足时只在内部审计保留公司范围判断及不能外推的原因，不输出公司产品结果，也不强造节点或链结论。
5. 同链不同节点可升温/降温并存。同节点多因素先综合净作用与条件；链级结论不是节点方向投票或平均值。判断主导环节、范围和时滞，不能把链结论复制给所有节点。
6. 链级只组织“推导逻辑、支持、反证”三类综合内容，体现上层因素与公司因素的实际作用；不按来源层级机械罗列。详情给每个受影响节点完整判断；公司事件和变量综合结论融入相关节点及链的推导逻辑、支持与反证，保留公司身份和 Event/Signal/Evidence 来源引用，不输出公司章节或卡片。公司原始变量信号及其直接判断存入内部 audit，不能改挂到节点变量表。
7. 上层锚点不是产业产品顶层宏观总结；保留其本工序判断在 audit，产品顶层按真实 Concept 聚合，无有效 Concept 映射的已评估链以正式链名独立总结；详情分别落到各链及其受影响节点；上层与公司分析均为本工序的推理中间结果。无真实图谱挂接、敞口不匹配或不能成立传导的公司，保留内部判断、原始信号及停止原因，不能造链来安置，也不能用独立公司章节代替传导分析。

### 公司到节点的具体判断

先按真实 Company ID 综合公司事件及自身变量信号，再查询冻结图谱中的业务挂接，沿真实关系定位 ChainNode 及其所属 IndustryChain。核对具体产品、业务分部、地域、时间和暴露机制；同一公司可关联多个节点、节点可属于多条链，但不能把公司全部变化自动传给所有关联对象。

例如公司某产品订单上升：先判断是否为已落地订单、与哪些业务节点对应，以及增长来自行业需求还是公司份额转移。图谱挂接和事实支持时，形成“公司相关产品订单增加 → 对应节点的需求获得支持 → 对所属链的影响”的有条件推理；若仅是份额转移，则不能据此判全节点需求升温。节点另有自身信号时综合判断；没有自身信号时标记 inferred，公司直接判断保留 audit。

每条采用或不采用的公司来源都须有审计落点：公司真实 ID、原始 Event/Signal/Evidence、变量综合与直接判断、查询到的真实关系路径、目标节点/链、经济机制、代表性及条件、目标报告位置或停止理由。报告用现有 reasoning_sources、链级 reasoning_summary 和 assessment 中合同允许的来源字段承载公司因素；audit 中的局部键不能作为报告内未定义对象的引用。若现有合同无法表达必要来源，应报告兼容缺口，不以添加公司章节绕过。

## 无信号、冲突与空结果

没有 Signal 不等于 Event 无效；检查是否足以形成条件性推理。自身 Signal 不适用时必须解释，不通过删除信号逃避判断。无法推导的节点不展示；链无可评估节点时不输出空链图。一个工序没有合格产品单元时保留空数组和真实原因，不能凑数量；当前整体空 Event 输入会被 CLI 拒绝，应记录取数状态，不声称生成了完整报告。

## 概念聚合与无归属链兜底

产业链工序必须读取并执行 [概念聚合规则](concept-aggregation.md)：有真实 Concept 关联时按概念综合；无关联时以产业链正式名称和真实 ICH 身份形成独立总结。不得伪造 Concept 或省略无关联链。
