# 产业链工序：概念聚合与无概念归属链兜底

这是产业链分支的强制产品组织与推理规则。两路独立性、Event/Signal 范围、变量综合、公司输入边界和节点传导规则保持不变。不能把结构缺失改成新的产品口径。

## 1. 取数与真实身份

- 冻结数据必须包含正式 Concept 的 ID/名称，以及有效 `IndustryChainMappedToConcept` 关系；用 ID 连接。逐页取齐并记录数量、哈希、查询时刻、环境。关系缺失或工具不支持时补齐能力，不按名称猜测、不沿用旧报告归属。
- 不把缺少正式 CON 身份的 ResearchConcept、研究标签、临时热点或推理结论当作市场 Concept。存在关系但端点无法定位时视为数据缺口，不能当成“无概念关联”。
- 图谱映射是分类依据，不是本期影响证据。不得修改图谱以适配报告。
- 修复既有报告时可保持原 Event/Signal 冻结范围并补查概念结构，但须分别记录原分析窗口和本次结构查询时刻，不伪称同一历史快照。不受影响的地缘/宏观工序可显式记录哈希后复用；产业工序独立分析，不读取这两路结论。

## 2. 先评估链和节点，再综合概念

1. 从四类 Event 及其相关信号做变量综合，沿真实公司→节点→链、地缘/宏观→链→节点路径，形成链和节点的基本面判断。公司自身信号/变量判断只保存在内部审计。
2. 对已评估链查询全部有效概念映射，逐关系判断产品、地域、技术及公司生态敞口是否适用。本期没有生态相关事实时，不因整链关联“某公司生态”就认定该生态受益。
3. 将有证据支持适用的链按 Concept ID 聚合。一概念一套总结及详情，同概念内同链只保留一份综合因果详情；多对多关系不强制简化成一链一概念。
4. 综合同概念下多条链的需求、供给、成本、利润、现金流影响，解释共同方向或分化、反证、时滞和条件，再写概念的一句话结论、箭头传导逻辑和影响度。不能复制一个链的结论当整个概念结论，也不以链条数、信号数投票或平均打分。
5. 概念没有自身信号时标 inferred，自身 variable_signals/variable_assessments 为空。不能把链、节点、公司的信号改挂给概念。各链/节点自己的变量仍在自己的详情对象内。

## 3. 没有概念关联的产业链

用户明确要求：没有概念关联的已评估产业链，用产业链正式名称作为一个独立总结单元，与概念总结在产业链栏目并列展示，一条链一套总结和因果链详情。

- 结构使用 `industry_chain_analyses`，source_id 保持真实 ICH ID，title 使用图谱产业链正式名称，detail.industry_chains 仅含自身链。
- “把产业链名当成概念”指总结展示粒度的兜底，不创建假 CON ID、不改变实体类型、不添加假的映射边、不在名称后追加“概念”等文案。
- 完整查询后确实没有有效映射，才可兜底；查询失败、映射端点缺失、有映射但没分析，均不能伪装成无关联。
- 有映射但证据不适用时，在审计中说明排除或限定原因，不得跳过概念适用性分析直接兜底。
- 无关联不等于无判断：原本有直接信号或有效传导的链/节点仍需分析并在报告保留；无法推导的节点继续不展示，不制造“暂无评估”占位。
- 不把本次“7条”写成今后固定数量。每次由冻结图谱和已评估链集合实际计算。

## 4. 数据组织

| 内容 | 发布位置 | 身份与引用 |
| --- | --- | --- |
| 概念总结 | concept_analyses[].summary | 根source_id为真实CON，title为正式概念名 |
| 概念详情及多链目录 | concept_analyses[].detail.industry_chains[] | 每链真实ICH，独立因果链及节点详情 |
| 无概念归属链总结 | industry_chain_analyses[].summary | 根为真实ICH，title为正式产业链名 |
| 兜底链详情 | industry_chain_analyses[].detail.industry_chains[0] | source_id与根相同 |

产业总结的 affected_refs 沿用已评估产业链节点口径：target_type=industry_chain_node，local_key引用节点判断，chain_local_key引用所在链。概念聚合改变的是总结根与多链组织，不改变原受影响节点口径，不引用概念自身。

单元内local_key与upstream_refs须闭包、无循环；同链出现在不同概念时保留相应上下文，统计同时提供链详情次数与真实ICH去重数，不能把重复展示当成更多产业链。

## 5. 校验与发布

公司级内容不构成报告结果数据：company_analyses、detail.companies为空，所有COM实体判断、公司变量表和公司信号只在内部audit。链/节点可以通过自身机制、支持与反证体现输入事实的作用，不能借嵌套对象、节点变量表或“公司传导详情”等章节重新输出公司级评估。发布前递归检查无COM source_id结果对象、无公司Signal行改挂、无悬空公司引用。HTML 同样不得保留空的公司导航、公司章节或“暂无公司评估”占位。

- 校验真实Concept类型/正式名称，一概念一总结、非空已评估链、同概念链去重，以及每条链到该Concept的真实映射。
- 校验独立链不存在有效Concept映射、标题正式、详情仅自身链；有映射的链不能全部塞进industry_chain_analyses绕过概念聚合。
- 逐Event/Signal审计、公司内部判断、每条映射采用/排除原因及未形成产品判断的链保留在audit；代码校验不能替代概念适用性和综合结论的人工语义审阅。
- HTML从已验收JSON渲染，不在渲染阶段临时拼概念。Data Service沿用现有v5的concept_analyses和industry_chain_analyses；v6原件仍保留variable_assessments，发布包移除该字段。
- 发布后逐概念/独立链读回总结、详情目录、每条链图谱及节点。验证两个数组的真实数量及独立分页，不假设Concept或独立链数组必须为空。

## 6. 行为验收

- 一个概念挂两条受相反因素影响的链：保留两条详情，概念结论解释分化及条件。
- 一条链挂两个概念：逐映射核对适用性，可在两个概念中出现；不能自动扩大到同概念全部链。
- 全量查询后无映射的已评估链：以真实ICH/正式链名独立发布，不能遗漏或伪造CON。
- 存在有效映射却绕过聚合：校验拒绝。
- 概念缺失、名称伪造、关系端点错误：阻断归属，不猜测、不静默兜底。
- 公司生态概念只有整链一般性信号：审阅生态敞口，缺依据时不传播成生态受益结论。
